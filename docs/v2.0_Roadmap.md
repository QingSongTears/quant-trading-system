# v2.0 Roadmap — 基于竞品研究的下一版本功能规划

> **版本**: v2.0 | **日期**: 2026-06-18 | **作者**: 项目 Leader
> **输入**: [竞品深度研究报告_v1.0.md](竞品深度研究报告_v1.0.md)
> **目标**: 在对标 Qlib/VectorBT/Zipline/QUANTAXIS 10个系统后，产出可落地的分阶段功能规划

---

## 一、规划原则（从竞品研究提炼）

| 原则 | 来源 | 落地决策 |
|------|------|---------|
| **事件驱动 = 核心范式** | Zipline / VectorBT | 保留 `BacktestEngine` 事件驱动，不切换为纯向量化 |
| **向量化 = 加速入口** | VectorBT | 新增 `VectorBacktestEngine` 作为可选后端，用于参数扫描/批量回测 |
| **因子 = 一等公民** | Qlib Alpha158 | 新增 `FactorEngine`，因子与策略解耦 |
| **微服务 = 扩展方向** | QUANTAXIS | v2.0 先预留接口抽象，不上微服务 |
| **AI = 未来武器** | FinRL / Qlib | v2.0 预留 `GymTradingEnv`，不实现 DRL |

## 三、Phase 2.0 详细规划（本 Phase 执行）

### 3.1 目标

> 对标 VectorBT 的**向量化回测** + Qlib 的**因子表达式引擎**，让参数扫描速度提升 100x，策略表达式可配置。

### 3.2 功能清单

#### **FE-01：回测引擎抽象层 `EngineGateway`** 🔴 P0

```
当前：BacktestEngine 硬编码事件驱动循环
目标：抽象 IEngine 接口，可切换事件驱动 / 向量化 两种后端

接口设计：
  IEngine:
    + run(strategy, data, initial_capital) → BacktestResult
    + set_mode(mode: "event" | "vector")
    + register_engine(name, engine_impl)

实现：
  - EngineGateway: 统一入口，根据 mode 路由到具体实现
  - EventEngine: 复用现有 BacktestEngine 逻辑
  - VectorEngine: 新实现，对标 VectorBT 向量化范式（Phase 2.0 只做框架，真正向量化在 T16 参数扫描中落地）
```

**验收标准**：
- [ ] `EngineGateway` 接口定义完整（含 `IEngine` 协议）
- [ ] 切换 `mode="event"` 回测结果与现有 `BacktestEngine` 完全一致（IC 差异 < 0.001）
- [ ] 代码覆盖率 > 80%（新增抽象层）

---

#### **FE-02：向量化批量回测（对标 VectorBT）** 🔴 P0

```
当前：param_server.py 中 for 循环逐组合扫描，128组合 ~60s
目标：一次矩阵运算，同时产出所有参数组合的权益曲线

设计要点：
  1. 数据：all_7d_scores.json → pandas DataFrame（N 行 × 7 维）
  2. 权重矩阵：W[M×D]（M=参数组合数，D=7 维度）
  3. 分数矩阵：S[N×D] × W^T → Score[N×M]（一次矩阵乘法）
  4. IC 计算：向量化 rankdata → 向量化 Spearman
  5. 输出：Top K 组合 + 维度重要性

预期性能：
  - 128 组合：60s → 0.5s（100x 提升）
  - 78,125 组合（精细模式）：~15min → ~2min
```

**验收标准**：
- [ ] `VectorEngine` 实现 `IEngine` 接口
- [ ] 128 组合扫描耗时 < 1s
- [ ] IC 结果与 `BacktestEngine` 差异 < 0.001
- [ ] 支持 `mode="vector"` 切换

---

#### **FE-03：Walk-Forward 优化** 🟡 P1

```
当前：BacktestEngine 已实现逐日重扫描（无未来数据泄露）
目标：增加 Walk-Forward 滑动窗口验证，输出参数稳定性曲线

功能：
  - 训练窗：252 交易日
  - 验证窗：63 交易日
  - 滑动步长：63 日
  - 输出：参数在验证窗的 IC 序列 → 稳定性评分
```

**验收标准**：
- [ ] Walk-Forward 分析报告（参数稳定性排名）
- [ ] 对比固定参数 vs Walk-Forward 参数的 OOS（样本外）IC 差异

---

#### **FE-04：投资组合回测** 🟡 P1

```
当前：单股回测，初始资金 100,000
目标：支持多股票组合回测，按策略权重分配资金

功能：
  - 资金分配：initial_capital 按 max_positions 等分
  - 组合权益曲线：多股权益叠加
  - 新增指标：组合 Sharpe / 最大回撤 / 胜率
```

**验收标准**：
- [ ] 多股组合回测结果与单股汇总一致
- [ ] 新增 `PortfolioResult` 数据类

## 六、风险与依赖

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| NumPy 矩阵内存爆炸（78,125 组合） | 中 | 分块计算（chunk_size=5000） |
| 向量化与事件驱动结果微小差异 | 高 | 保留事件驱动为 Gold Standard，差异 < 0.001 方可发布 |
| 因子表达式引擎语法复杂 | 中 | 第一期只支持 10 个基础算子，不开放自定义 |
| Walk-Forward 耗时较长 | 低 | 用向量化引擎加速 |
