## 2. 需求背景与目标

### 2.1 需求来源确认

| 决策项 | 确认结果 |
|--------|----------|
| 股票范围 | **全市场**（上交所、深交所、北交所全部上市A股，约 5500 只） |
| 历史数据时间范围 | **近 3 年**（2022-06 ~ 2025-06，约 750 个交易日） |
| 数据库选型 | **SQLite**（单文件零配置） |
| 数据真实性 | **所有数据必须来自可考证的公开数据源，禁止任何模拟/伪造数据** |
| AI 内容标注 | **所有 AI 生成的分析、建议、总结，必须显式标注「AI生成」** |

### 2.2 业务背景

A股市场每日产生海量交易数据。量化策略研究者的核心工作流为：

```
研究策略思路 → 下载历史数据 → 编写策略代码 → 回测验证 → 对比不同策略 → 迭代优化
```

当前这个流程在各环节之间存在断裂：数据需要手动抓取、回测结果散落在不同工具中、缺乏统一的对比视图。本系统旨在将上述工作流整合为一条完整的本地化工具链。

### 2.3 核心目标（OKR）

| 目标 | 关键结果 | 衡量方式 |
|------|----------|----------|
| **O1**: 一键获取全市场历史数据 | KR1: 全市场 5500+ 只股票近 3 年日线数据下载完成率 ≥ 95% | 数据库记录数 vs 实际交易日×股票数 |
| **O2**: 策略回测标准化 | KR2: 任意策略可在 30 秒内完成单只股票 3 年回测 | 计时测试 |
| **O3**: Web 可视化可交互 | KR3: 6 个核心页面均可通过浏览器访问且图表正常渲染 | 手动验收 |
| **O4**: 多模型横向对比 | KR4: 支持同时展示 5+ 策略的净值曲线叠加图和指标对比表 | 手动验收 |

## 3. 用户故事

### US-1: 一键下载全市场数据

> **作为** 量化策略研究员  
> **我希望** 执行一条命令或点击一个按钮，就能自动下载沪深京三地全部A股近 3 年的日线数据并持久化到本地 SQLite 数据库  
> **以便** 我拥有一个完整的离线数据集，随时供回测调用，无需关心数据源的接口变化

**优先级**: P0（核心依赖，所有回测功能的前置条件）

### US-2: 增量更新数据

> **作为** 量化策略研究员  
> **我希望** 系统记录上次下载的时间，后续只需要拉取增量数据  
> **以便** 每天更新不会重复下载已有的历史数据，节省时间和网络带宽

**优先级**: P1

### US-3: 编写并注册自定义策略

> **作为** 策略研究员  
> **我希望** 通过继承基类、编写 `init()` 和 `next()` 两个方法，然后用一个 YAML 配置文件注册策略  
> **以便** 我专注于策略逻辑本身，无需处理数据对接、订单模拟、指标计算等底层细节

**优先级**: P0

### US-4: 运行单策略回测并查看报告

> **作为** 策略研究员  
> **我希望** 在 Web 界面选择策略、股票、日期范围，点击运行，然后在同一页面看到完整的回测结果  
> **以便** 快速验证策略思路是否可行

**优先级**: P0

### US-5: 多策略横向对比

> **作为** 策略研究员  
> **我希望** 同时选择多个已注册的策略，对同一只股票同一时间段运行回测，并在一个页面并排对比所有结果  
> **以便** 一目了然地判断哪个策略在当前标的上表现更好

**优先级**: P1

### US-6: 回测结果历史管理

> **作为** 策略研究员  
> **我希望** 所有历史回测结果自动保存，可以随时回溯查看  
> **以便** 跟踪策略迭代过程中的表现变化

**优先级**: P2

### US-7: 相似回测智能检索 (v1.1 新增)

> **作为** 策略研究员  
> **我希望** 在查看某次回测结果时，系统自动检索历史中最相似的 N 次回测并展示  
> **以便** 快速找到可类比的历史案例，辅助判断当前策略的可靠性

**优先级**: P3（后续版本）
**灵感来源**: Vibe Trading 的 BM25 记忆系统

### US-8: 风控指标分析 (v1.1 新增)

> **作为** 策略研究员  
> **我希望** 回测报告不仅包含收益指标，还包含 VaR（在险价值）、凯利公式建议仓位、压力测试等风控指标  
> **以便** 在实盘前全面评估策略的风险特征

**优先级**: P2
**灵感来源**: Vibe Trading 的风控框架

## 5. 功能详细描述 (EARS)

### F1: 历史数据下载引擎

#### F1.1 数据下载（Event-driven）

> **When** 用户触发数据下载命令（CLI 或 Web 按钮），  
> **the system shall** 调用 AKShare 接口 `ak.stock_zh_a_hist()` 逐只下载全市场A股日线数据，  
> **and** 每条记录包含以下字段：股票代码、交易日期、开盘价、最高价、最低价、收盘价、成交量、成交额、涨跌幅、换手率。

| 字段 | 类型 | 说明 | 数据来源 |
|------|------|------|----------|
| `code` | VARCHAR(10) | 股票代码，如 '000001' | AKShare |
| `trade_date` | DATE | 交易日期 | AKShare |
| `open` | DECIMAL(10,3) | 开盘价 | AKShare |
| `high` | DECIMAL(10,3) | 最高价 | AKShare |
| `low` | DECIMAL(10,3) | 最低价 | AKShare |
| `close` | DECIMAL(10,3) | 收盘价 | AKShare |
| `volume` | BIGINT | 成交量（股） | AKShare |
| `amount` | DECIMAL(18,2) | 成交额（元） | AKShare |
| `pct_change` | DECIMAL(8,4) | 涨跌幅（%） | AKShare |
| `turnover` | DECIMAL(8,4) | 换手率（%） | AKShare |

#### F1.2 全量下载模式（Event-driven）

> **When** 用户首次运行下载（数据库中无数据），  
> **the system shall** 遍历所有A股代码，逐一调用 AKShare 下载近 3 年日线数据，  
> **and** 显示实时进度条（当前股票序号/总股票数、已完成百分比、预计剩余时间）。

#### F1.3 增量更新模式（State-driven）

> **While** 数据库中已存在历史数据，  
> **the system shall** 查询每只股票的最新数据日期，仅下载该日期之后的新增交易日数据，  
> **and** 以 `UPSERT` 模式写入数据库（按 `code + trade_date` 唯一键去重）。

#### F1.4 下载异常处理（Unwanted）

> **If** 某只股票下载失败（网络超时、接口返回异常、该股票已退市无近期数据），  
> **then the system shall** 记录该股票代码和错误原因到日志文件，  
> **and** 跳过该股票继续下载下一只，  
> **and** 在下载完成后汇总失败清单并展示给用户。

#### F1.5 下载限速（Ubiquitous）

> **The system shall** 在连续请求之间设置 0.5~1 秒的间隔，  
> **and** 在请求头中标注合理的 User-Agent，  
> **to** 避免对 AKShare 数据源造成过大压力或触发反爬机制。

#### F1.6 备选数据源（Unwanted）

> **If** AKShare 接口长时间不可用（连续失败 10 次以上），  
> **then the system shall** 自动切换到 Baostock 作为备选数据源继续下载，  
> **and** 在日志中标注使用了备选数据源。

#### F2.3 数据查询接口（Ubiquitous）

> **The system shall** 提供以下标准数据查询方法（Repository 层）：

```python
get_stock_list(market: str = None) -> List[StockBasic]
get_daily_data(code: str, start: date, end: date) -> pd.DataFrame
get_latest_date(code: str) -> date | None
get_data_coverage() -> dict  # 返回数据覆盖统计
```

#### F2.4 数据完整性校验（Event-driven）

> **When** 数据下载完成后，  
> **the system shall** 自动执行完整性校验：
> - 对比数据库中每只股票的记录数与理论交易日数（约 750 天）
> - 检查是否存在价格为 0 或为 NULL 的异常记录
> - 检查是否存在重复的 `(code, trade_date)` 记录
>
> **and** 输出校验报告：
> - 总股票数、总记录数
> - 数据完整度 ≥ 90% 的股票占比
> - 异常记录清单

#### F2.5 数据真实性声明（Ubiquitous）

> **The system shall** 在数据库初始化时记录数据来源元信息：数据源名称、下载时间、数据时间范围、  
> **and** 在 Web 界面的数据管理页显式标注数据来源（如 "数据来源: AKShare (akshare.readthedocs.io)"），  
> **and** 所有数据写入前必须保留原始值，禁止任何形式的插值填充、随机生成或模拟。

### F3: 策略开发框架

#### F3.1 策略基类（Ubiquitous）

> **The system shall** 提供 `BaseStrategy` 抽象基类，继承自 `backtesting.Strategy`，  
> **and** 封装以下通用能力：

```python
class BaseStrategy(Strategy):
    """用户策略基类 - 本系统所有策略必须继承此类"""
    
    # 策略元信息（子类必须覆盖）
    name: str
    description: str
    
    def init(self):
        """初始化 - 在此方法中计算技术指标"""
        pass
    
    def next(self):
        """每个交易周期调用一次 - 在此方法中编写买卖逻辑"""
        pass
    
    # 内置辅助方法
    def sma(self, period: int) -> pd.Series: ...
    def ema(self, period: int) -> pd.Series: ...
    def rsi(self, period: int) -> pd.Series: ...
    def macd(self) -> tuple: ...
    def bollinger_bands(self, period: int, std: float) -> tuple: ...
```

#### F3.2 策略注册（Event-driven）

> **When** 用户在 `strategies/` 目录下创建新的策略 Python 文件，  
> **and** 在 `config/strategies.yaml` 中添加策略配置条目，  
> **the system shall** 在启动时自动扫描并加载所有已注册策略。

**YAML 配置格式**:

```yaml
# config/strategies.yaml
strategies:
  - name: "双均线交叉"
    class_path: "strategies.ma_cross.MACrossStrategy"
    params:
      fast_period: 5
      slow_period: 20
    description: "当短期均线上穿长期均线时买入，下穿时卖出"
    
  - name: "RSI均值回归"
    class_path: "strategies.rsi_reversal.RSIReversalStrategy"
    params:
      rsi_period: 14
      oversold_threshold: 30
      overbought_threshold: 70
    description: "RSI低于超卖线买入，高于超买线卖出"
```

#### F3.3 策略参数验证（Unwanted）

> **If** 策略配置中的参数类型或范围不合法（如周期参数为负数），  
> **then the system shall** 在加载时抛出明确的 `StrategyConfigError` 异常，  
> **and** 在 Web 界面显示具体错误信息，阻止回测执行。

#### F3.4 预设策略模板（Optional）

> **Where** 系统提供预设策略模板，  
> **the system shall** 内置以下 5 个可考证的经典策略实现：

| 策略 | 类型 | 经典来源 |
|------|------|----------|
| 双均线交叉 | 趋势跟踪 | J. Welles Wilder 概念 |
| MACD 金叉死叉 | 趋势跟踪 | Gerald Appel (1979) |
| RSI 超买超卖 | 均值回归 | J. Welles Wilder (1978) |
| 布林带突破 | 波动率策略 | John Bollinger (1980s) |
| 海龟交易法则 | 趋势跟踪 | Richard Dennis (1983) |

> **所有预设策略的代码注释中须标注策略来源文献**，以确保可考证性。

### F4: 回测引擎

#### F4.1 回测执行（Event-driven）

> **When** 用户通过 Web 界面或 CLI 触发回测，  
> **the system shall** 执行以下流程：

```
1. 从数据库查询指定股票在指定日期范围内的日线数据
2. 将数据转换为 Backtesting.py 要求的 OHLCV DataFrame 格式
3. 初始化策略实例（注入配置参数）
4. 运行回测（含交易成本模拟）
5. 收集回测统计数据
6. 生成标准化 BacktestReport
7. 将结果写入 backtest_result 表
8. 返回报告给前端渲染
```

#### F4.2 交易成本模拟（Ubiquitous）

> **The system shall** 在回测中默认模拟以下交易成本：

| 成本项 | 默认值 | 可配置 | 依据 |
|--------|--------|--------|------|
| 佣金费率 | 0.03%（双边） | ✅ | A股券商行业常见费率 |
| 印花税 | 0.05%（仅卖出） | ✅ | 中国财政部规定（2023年8月起减半征收） |
| 滑点 | 0.01% | ✅ | 保守估计 |
| 最小佣金 | 5 元/笔 | ✅ | 券商最低收费标准 |

#### F4.3 标准化回测报告（Ubiquitous）

> **The system shall** 为每次回测输出以下标准化指标：

| 指标 | 英文名 | 计算公式 |
|------|--------|----------|
| 总收益率 | Total Return | `(最终权益 / 初始资金 - 1) × 100%` |
| 年化收益率 | Annual Return | `((1 + 总收益率)^(365/交易日数) - 1) × 100%` |
| 夏普比率 | Sharpe Ratio | `(年化收益率 - 无风险利率) / 年化波动率`，无风险利率默认 2% |
| 最大回撤 | Max Drawdown | `max((峰值 - 谷值) / 峰值) × 100%` |
| 胜率 | Win Rate | `盈利交易次数 / 总交易次数 × 100%` |
| 盈亏比 | Profit Factor | `总盈利金额 / 总亏损金额` |
| 总交易次数 | Total Trades | 完整买卖配对次数 |
| 年化波动率 | Annual Volatility | `日收益率标准差 × sqrt(250)` |
| 卡玛比率 | Calmar Ratio | `年化收益率 / 最大回撤` |

#### F4.4 基准对比（Event-driven）

> **When** 回测完成，  
> **the system shall** 同时计算同期沪深300指数的表现作为基准对比，  
> **and** 在报告中展示策略相对于基准的超额收益（Alpha）。

沪深300数据来源：AKShare `ak.stock_zh_index_daily(symbol="sh000300")`，同样存入数据库。

#### F4.5 回测结果持久化（Event-driven）

> **When** 回测完成，  
> **the system shall** 将完整报告序列化后写入 `backtest_result` 表，  
> **and** 净值曲线数据以 JSON 数组格式存储在 `equity_curve` 字段（格式: `[{"date":"2023-01-03","equity":100000}, ...]`），

策略:[策略名] 标的:[股票代码] 行业:[行业]

### F8: 风控分析框架 　🔵 v1.1 新增 · P2 · 灵感: Vibe Trading

#### F8.1 VaR 在险价值计算（Ubiquitous）

> **The system shall** 在每次回测报告中自动计算以下 VaR 指标：

| 指标 | 计算方式 | 含义 |
|------|----------|------|
| **历史 VaR (95%)** | 日收益率分布的第 5 百分位数 × 初始资金 | 95% 置信度下，单日最大亏损不超过此金额 |
| **历史 VaR (99%)** | 日收益率分布的第 1 百分位数 × 初始资金 | 99% 置信度下的极端风险 |
| **CVaR (95%)** | 低于 VaR(95%) 的所有日收益率均值 | 条件在险价值，衡量尾部风险的平均值 |

#### F8.2 凯利公式仓位建议（Optional）

> **Where** 策略有足够的交易记录（≥ 20 笔），  
> **the system shall** 基于历史交易的胜率和盈亏比，  
> **and** 使用凯利公式计算建议仓位比例：

```
f* = (bp - q) / b

其中:
  b = 平均盈利 / 平均亏损（盈亏比）
  p = 胜率
  q = 1 - p（亏损概率）
```

> **and** 展示三种仓位建议：
> - **凯利全仓**: f* × 100%
> - **半凯利**: f* × 50%（更保守稳健）
> - **四分之一凯利**: f* × 25%（最保守）

> **and** 显式标注：
> 🔵 **风险警告**: 凯利公式基于历史数据计算，假设未来分布与历史一致。实际交易中建议使用半凯利或更保守的仓位。

#### F8.3 压力测试（Optional）

> **Where** 用户选择压力测试模式，  
> **the system shall** 对策略进行以下情景模拟：

| 情景 | 模拟方式 | 展示指标 |
|------|----------|----------|
| **2008 年级别暴跌** | 在回测数据中插入一段 -50% 的价格冲击 | 最大回撤、恢复天数 |
| **2015 年级别股灾** | 连续多日跌停（-10%/天 × 5天） | 是否止损、亏损金额 |
| **震荡市** | 限制价格波动在 ±5% 内 | 交易频率变化、盈亏变化 |
| **流动性枯竭** | 增加滑点至 2% | 对收益的侵蚀百分比 |

#### F8.4 风控指标展示（State-driven）

> **While** 用户在回测详情页查看「风控分析」tab，  
> **the system shall** 展示：

1. **风险概览卡片**: VaR(95%)、VaR(99%)、CVaR、年化波动率
2. **仓位建议卡片**: 凯利仓位、半凯利、四分之一凯利（含计算参数）
3. **回撤分析**: 最大回撤、回撤持续天数、恢复天数
4. **压力测试结果**: 各情景下的策略表现表格
5. 🔵 **AI 生成风险解读**: 「AI生成」标注的策略风险特征文字总结

#### F8.5 风控数据模型扩展

> **The system shall** 在 `backtest_result` 表中新增以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `var_95` | FLOAT | 95% 置信度 VaR |
| `var_99` | FLOAT | 99% 置信度 VaR |
| `cvar_95` | FLOAT | 95% 条件 VaR |
| `kelly_fraction` | FLOAT | 凯利公式建议仓位比例 |
| `half_kelly` | FLOAT | 半凯利仓位 |

| 数据项 | 来源 | 可考证方式 | 说明 |

### 6.2 数据真实性保障措施

> **The system shall** 实施以下多层保障：

1. **禁止模拟数据**：代码中不得包含任何硬编码的股价数据、随机生成函数
2. **来源可追溯**：数据库中的 `data_source` 元信息字段记录每条数据的来源和下载时间
3. **原始值写入**：数据写入数据库前不进行任何填充、平滑、修正处理
4. **Web 界面溯源展示**：数据管理页展示数据来源链接，每个回测结果附数据时间戳
5. **一致性抽样校验**（P2）：随机抽取 10 只股票 × 5 个日期，交叉对比东方财富网页数据

### 6.3 不使用的数据类型

> **The system shall NOT** 包含以下无法考证的数据：
> - ❌ 任何预测性质的数据（如分析师预测目标价）
> - ❌ 任何基于推测的财务数据
> - ❌ 任何未经交易所公开披露的内幕或非公开信息
> - ❌ 任何 AI 生成的模拟价格序列
> - ❌ 任何复权计算中自行估算的除权除息因子（须使用 AKShare 提供的复权因子或前复权价格）

## 9. 数据口径与指标体系

### 9.1 核心指标计算口径

| 指标 | 口径 | 说明 |
|------|------|------|
| 收益率 | 简单收益率（非对数收益率） | `(V_end - V_start) / V_start` |
| 年化收益率 | 按实际交易日年化 | CAGR = `(V_end/V_start)^(250/trading_days) - 1` |
| 无风险利率 | 默认 2%（一年期定存近似） | 可配置 |
| 波动率 | 日收益率标准差年化 | `std(daily_returns) × sqrt(250)` |
| 最大回撤 | 滚动峰值到谷值 | `max_drawdown = min((V_t - peak) / peak)` |
| 夏普比率 | 标准定义 | `(annual_return - rf) / annual_volatility` |
| 基准 | 沪深300全收益 | 同期持有沪深300的收益率 |

## 11. 边界场景与异常处理

### 11.1 数据下载异常

| 场景 | 处理方式 |
|------|----------|
| 网络断开 | 记录已下载进度，支持断点续传 |
| 单只股票接口超时（>30s） | 跳过并记录，继续下一只 |
| 连续 10 只失败 | 暂停 5 分钟后自动重试 |
| 某只股票已退市无近期数据 | 标记为"退市"，记录最后交易日期 |
| AKShare 接口整体不可用 | 自动切换 Baostock，并在日志中标注 |
| 磁盘空间不足 | 下载前检查可用空间（至少保留 2GB），不足则阻止下载并提示 |

### 11.2 数据库异常

| 场景 | 处理方式 |
|------|----------|
| 数据库文件损坏 | 提示用户备份路径，引导重新下载 |
| 写入冲突（并发回测） | SQLite 写锁，排队执行 |
| 数据量过大导致查询慢 | 通过索引优化，超过 5 秒的查询在日志中标记 |

### 11.3 回测异常

| 场景 | 处理方式 |
|------|----------|
| 股票在回测区间内无数据 | 提示"该股票在选定时间段内无交易数据" |
| 策略产生连续错误信号 | 不中断回测，在结果中标注异常 |
| 初始资金不足以买入一手 | 提示"初始资金不足以买入最小交易单位（100股）" |
| 策略从未产生交易 | 回测正常完成，报告中总交易次数=0 |

### 11.4 Web 服务异常

| 场景 | 处理方式 |
|------|----------|
| 端口被占用 | 自动尝试下一个端口（5050→5051→5052） |
| ECharts CDN 无法加载 | 页面显示"图表加载失败，请检查网络连接" |
| 数据库未初始化 | 自动跳转到数据管理页引导下载 |

### 11.5 A股特殊规则处理

| 规则 | 处理方式 |
|------|----------|
| T+1 交易制度 | 策略中当日买入次日才能卖出，在回测引擎中配置 `trade_on_close=True` 模拟次日可卖 |
| 涨跌停限制（±10%/±20%） | 在策略基类中提供 `is_limit_hit()` 辅助方法；回测引擎层面不阻止超限价下单，但报告底部标注"未模拟涨跌停限制" |
| 最小交易单位 100 股 | 回测引擎中设置 `size=100` 确保每笔交易为整手 |
