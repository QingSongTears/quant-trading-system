## 1. 需求背景与目标

### 1.1 业务背景

A股市场（沪深京三地交易所）涵盖超过 5000 只股票，日线级别数据量庞大。量化交易在国内已从机构专属走向个人研究者可及的阶段，但存在以下痛点：

| 痛点 | 描述 |
|------|------|
| **数据获取分散** | 免费数据源很多（AKShare、Tushare、Baostock），但各自接口不同，缺乏统一本地化管理 |
| **回测框架碎片化** | Backtrader、Zipline、vnpy 等各有优劣，选型困难且学习曲线陡峭 |
| **多模型对比困难** | 不同策略模型的回测结果难以在同一平台上横向对比 |
| **可视化薄弱** | 大部分回测结果以命令行或静态图表输出，缺乏交互式 Web 前端展示 |
| **数据持久化缺失** | 每次回测都重新拉取数据，没有本地数据库缓存机制 |

### 1.2 项目目标

构建一个**本地化部署**的A股量化交易模型系统，核心目标：

1. **一键下载 & 存储**：自动下载A股全量历史日线数据并持久化到本地数据库
2. **多策略模型管理**：支持同时注册、配置和运行多个量化策略模型
3. **统一回测引擎**：基于成熟回测框架封装，输出标准化回测指标
4. **HTML Web 可视化**：通过浏览器展示回测结果，包括收益曲线、回撤、夏普比率等关键指标
5. **横向对比**：多模型回测结果在同一页面上并排对比

### 1.3 非目标（本期不做）

- ❌ 实盘交易接口对接（后续版本）
- ❌ 分钟级/Tick级高频数据
- ❌ 机器学习模型训练平台
- ❌ 多用户/权限管理
- ❌ 云端部署

## 3. 竞品与现有方案分析

### 3.1 主流回测框架对比

| 框架 | 优点 | 缺点 | 适合场景 |
|------|------|------|----------|
| **Backtrader** | 文档丰富、社区活跃、指标库完整 | 速度较慢、API老旧、不支持Pandas 2.x | 策略研究、快速原型 |
| **Backtesting.py** | 轻量、速度快、API 简洁现代 | 功能较少、不支持多资产组合 | 简单策略快速验证 |
| **Zipline-Reloaded** | 事件驱动架构、Pipeline API强大 | 安装复杂、社区萎缩、数据管理弱 | 美股为主，A股需适配 |
| **Qlib (微软)** | AI 原生、数据管理强、模型库丰富 | 学习曲线陡、偏学术、前端弱 | AI/ML 量化研究 |
| **vnpy** | 全功能平台、实盘对接强、国内社区大 | 过于庞大、不易拆解、偏期货 | 期货/实盘交易 |
| **VectorBT** | 向量化回测极快、可视化强 | 非事件驱动、策略表达受限 | 参数扫描和优化 |

### 3.2 数据源对比

| 数据源 | 免费额度 | 数据覆盖 | 安装难度 | 推荐场景 |
|--------|----------|----------|----------|----------|
| **AKShare** ⭐ | 完全免费 | 沪深京A股、指数、基金 | 极低 (`pip install`) | **首推** — 无需注册，接口丰富 |
| **Tushare** | 有限免费(需积分) | A股全量+财务数据 | 低 | 需要财务数据时 |
| **Baostock** | 完全免费 | A股日线、分钟线 | 极低 | 补充数据源 |

### 3.3 我们的差异化定位

> **不做另一个回测框架，而是做一个"数据管理 + 多模型对比 + Web可视化"的集成工作台。**

```
现有工具：数据下载(手动) → 回测(命令行) → 看图(Matplotlib弹出窗口)
我们的系统：数据下载(一键) → 多模型回测(配置化) → 结果对比(Web浏览器)
```

## 4. 用户故事

### US-1: 数据管理

> **作为** 量化策略研究员  
> **我希望** 一键下载全部A股历史日线数据并存储到本地数据库  
> **以便** 我可以随时离线使用这些数据，无需每次回测都重新拉取

**验收标准**:
- The system shall 提供命令行工具一键触发全量数据下载
- When 下载完成后, the system shall 将数据存入 SQLite/PostgreSQL 数据库
- The system shall 支持增量更新（仅下载数据库中缺失的日期）
- If 某只股票数据下载失败, then the system shall 记录错误日志并继续下载其他股票
- The system shall 支持按股票代码、日期范围查询数据

### US-2: 策略模型开发

> **作为** 策略研究员  
> **我希望** 基于统一的策略基类开发自定义交易策略  
> **以便** 我只需要关注买卖信号逻辑，无需处理数据对接和回测底层

**验收标准**:
- The system shall 提供标准策略基类（`BaseStrategy`），包含 `init()`, `next()`, `on_order()` 等钩子
- When 策略产生买卖信号, the system shall 自动计算手续费、滑点等交易成本
- The system shall 支持策略参数的外部配置（YAML/JSON 配置文件）

### US-3: 多模型回测

> **作为** 策略研究员  
> **我希望** 同时运行多个策略模型对同一时间段的历史数据进行回测  
> **以便** 我可以横向对比哪个策略表现更好

**验收标准**:
- The system shall 支持批量回测：一次命令运行 N 个策略
- The system shall 每个策略输出标准化的回测报告（收益率、夏普比率、最大回撤、胜率等）
- When 多个策略回测完成, the system shall 生成统一的对比汇总表

### US-4: Web 可视化

> **作为** 策略研究员  
> **我希望** 在浏览器中查看回测结果的可视化图表  
> **以便** 我可以直观地判断策略表现

**验收标准**:
- The system shall 提供一个本地 Web 服务器显示回测结果
- The system shall 展示：净值曲线、回撤曲线、年度收益柱状图、月度收益热力图
- When 用户选择多个策略, the system shall 在同一图表上叠加显示多条净值曲线
- The system shall 展示交易明细列表（买卖时间、价格、盈亏）

### 6.1 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                     Web 可视化层 (前端)                       │
│              HTML5 + ECharts + Bootstrap                     │

│                     API 服务层                               │
│              Flask / FastAPI (REST API)                      │
├─────────────────────────────────────────────────────────────┤
│                     业务逻辑层                                │
│  ┌───────────┐  ┌───────────┐  ┌───────────┐               │
│  │ 数据下载   │  │  回测引擎  │  │ 策略管理   │               │
│  │ 引擎       │  │  (封装层)  │  │ (注册/对比)│               │
│  └───────────┘  └───────────┘  └───────────┘               │
├─────────────────────────────────────────────────────────────┤
│                     数据持久层                                │
│              SQLite (单机) / PostgreSQL (可选)               │
│              存储: 日线数据 + 回测结果 + 策略配置              │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 核心技术栈

| 层级 | 技术选型 | 选型理由 |
|------|----------|----------|
| **语言** | Python 3.10+ | 量化生态最完善 |
| **数据获取** | AKShare | 免费、无需注册、A股覆盖全 |
| **回测框架** | Backtesting.py | 轻量、API现代、与 Pandas 无缝集成 |
| **数据库** | SQLite（默认） + SQLAlchemy ORM | 零配置、单文件、足够支撑千万级数据 |
| **Web 后端** | FastAPI | 高性能、自动生成API文档、异步支持 |
| **Web 前端** | Jinja2 模板 + ECharts + Bootstrap 5 | 纯静态 HTML、CDN引入、零前端构建 |
| **数据分析** | Pandas + NumPy | 数据处理基石 |
| **指标计算** | TA-Lib / pandas-ta | 技术指标库 |
| **配置管理** | YAML | 策略参数和系统配置 |

### 6.3 为什么选 Backtesting.py 而不是 Backtrader？

| 维度 | Backtesting.py | Backtrader |
|------|---------------|------------|
| 代码量 | ~3000 行 | ~50000 行 |
| 学习成本 | 1 小时上手 | 1-2 周 |
| API 风格 | 现代化、Pythonic | 老旧、继承层次深 |
| Pandas 集成 | 原生支持 | 需适配 |
| 速度 | 快（向量化辅助） | 较慢（纯事件驱动） |
| 多策略同时回测 | 支持 | 支持但复杂 |

> **结论**: 对于本项目「原型验证 + 个人研究」的定位，Backtesting.py 是更好的选择。

## 9. 多模型管理与回测引擎

### 9.1 策略基类设计

```python
# 策略开发只需继承基类，实现 init() 和 next()
from backtesting import Strategy

class BaseStrategy(Strategy):
    """用户策略基类，封装通用逻辑"""
    
    # 策略元信息（必须覆盖）
    name: str = "base"
    description: str = ""
    
    def init(self):
        """初始化指标计算"""
        pass
    
    def next(self):
        """每个bar调用一次，决策逻辑"""
        pass
    
    # 内置辅助方法
    def compute_indicators(self, data):
        """计算常用技术指标 (SMA, EMA, MACD, RSI, etc.)"""
        pass
```

### 9.2 策略注册机制

```yaml
# strategies/registry.yaml
strategies:
  - name: "双均线交叉"
    class: "strategies.ma_cross.MACrossStrategy"
    params:
      fast_period: 5
      slow_period: 20
      
  - name: "RSI超买超卖"
    class: "strategies.rsi_reversal.RSIReversalStrategy"
    params:
      rsi_period: 14
      oversold: 30
      overbought: 70
```

### 9.3 回测标准化输出

每次回测输出标准化的 `BacktestReport`：

```python
@dataclass
class BacktestReport:
    strategy_name: str
    start_date: date
    end_date: date
    initial_capital: float
    final_equity: float
    total_return: float        # 总收益率 (%)
    annual_return: float       # 年化收益率 (%)
    sharpe_ratio: float        # 夏普比率
    sortino_ratio: float       # 索提诺比率
    max_drawdown: float        # 最大回撤 (%)
    win_rate: float            # 胜率 (%)
    profit_factor: float       # 盈亏比
    total_trades: int          # 总交易次数
    equity_curve: list[dict]   # [{date, equity}, ...] 供前端绘图
    trades: list[dict]         # 交易明细
    monthly_returns: dict      # 月度收益率矩阵
    benchmark_compare: dict    # 与基准（如沪深300）对比
```

## 11. 风险评估与注意事项

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| **AKShare 接口不稳定** | 🔴 高 | 添加 Baostock 备选数据源；数据下载后本地存储，不依赖实时接口 |
| **SQLite 大数据量性能** | 🟡 中 | 对日期和代码建联合索引；如数据量超预期，可迁移到 DuckDB（零配置替代） |
| **回测结果与实际偏差** | 🟡 中 | 明确标注回测假设（无涨跌停限制、无流动性约束）；文档说明局限性 |
| **Backtesting.py 功能瓶颈** | 🟢 低 | 初期够用，后续可平滑迁移到 VectorBT 或自研引擎 |
| **数据版权/合规** | 🟡 中 | 仅使用公开免费数据源；数据仅限个人研究使用，不对外分发 |

### 关键技术决策说明

> ⚠️ **Backtesting.py 的已知限制**：
> - 不支持多资产组合同时回测（单次回测一个股票+一个策略）
> - 不支持日内数据（仅日线及以上级别）
> - 不支持 A 股特有的涨跌停限制
>
> **本系统的解决方案**：在引擎封装层通过循环实现多股票批量回测，在报告中汇总结果。涨跌停限制在策略基类的 `next()` 中通过逻辑判断实现。
